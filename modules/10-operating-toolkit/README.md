# Module 10: Operating Toolkit

Status: draft

## Purpose

This module turns the accepted practices in Modules 00-09 into a small
private-first operating toolkit.

The central rule is:

> use the smallest record that answers the current question, then close it when
> the purpose ends.

The blank templates live in [toolkit/](../../toolkit/README.md).

## Owner-first design

Existing module records remain authoritative:

- Module 00 defines the M/S/E evidence record;
- Module 01 defines honest assessment;
- Modules 02-03 define advocacy and pathway action;
- Modules 04-05 define management and team signals;
- Module 06 defines movement;
- Module 07 defines environment diligence;
- Module 08 defines transition continuity;
- Module 09 defines ethical use.

Module 10 does not replace those semantics. It contributes:

- a selection map;
- blank portable templates;
- a private-to-shared boundary;
- a simple operating loop;
- archive and deletion rules;
- software admission gates.

## The minimum operating loop

```text
Choose
  -> Capture
  -> Interpret
  -> Act
  -> Review
  -> Close
```

### 1. Choose

Choose one current question.

Examples:

```text
Does my manager currently advocate for the scope I own?
Why is context not reaching this team?
Did one bounded action create better next-level evidence?
What changed after the reorganization?
Is this role environment safe enough for me?
Can I share this record ethically?
```

Do not begin by filling every template.

### 2. Capture

Capture:

- purpose;
- date or evidence window;
- observable evidence;
- counterevidence;
- unknowns;
- structural context;
- privacy or safety concern.

Do not score first.

### 3. Interpret

Interpret only what the evidence supports:

- current M/S/E range or `unknown`;
- pathway failure or uncertainty;
- movement state;
- commitment status;
- environment risk or unknown.

Do not infer performance, potential, intent, loyalty, or outcome.

### 4. Act

Choose one:

- ask one safer question;
- create one bounded evidence opportunity;
- correct attribution;
- clarify one commitment;
- change one pathway;
- seek a qualified protected route;
- take no action until relevant evidence exists.

The action is not "raise the score."

### 5. Review

Review on a named event:

- an advocacy act;
- a consequential decision;
- a completed experiment;
- a manager or role change;
- a commitment disposition;
- new counterevidence;
- a safety or privacy change.

Avoid calendar rescoring performed only to create motion.

### 6. Close

When the purpose ends:

- preserve a dated historical snapshot if still useful;
- remove shared access;
- archive only what remains necessary;
- delete excessive, stale, or unsafe material;
- close or transfer commitments;
- record why the file remains.

## Template selection

| Current need | Use | Do not use it for |
|---|---|---|
| current advocacy evidence | [Private profile](../../toolkit/templates/private-profile.md) | employment decisions or comparison |
| one pathway change | [Pathway experiment](../../toolkit/templates/pathway-experiment.md) | activity or visibility quotas |
| team or management signal | [Team signal](../../toolkit/templates/team-signal.md) | a hidden team or manager score |
| prospective environment | [Environment diligence](../../toolkit/templates/environment-diligence.md) | candidate or manager classification |
| manager, role, team, or leave change | [Transition](../../toolkit/templates/transition.md) | automatic score resets |
| disclosed development discussion | [Shared conversation](../../toolkit/templates/shared-conversation.md) | sharing the full private file |
| any sharing, aggregation, or reuse | [Ethical-use check](../../toolkit/templates/ethical-use-check.md) | making prohibited use acceptable |

## Ten-minute private start

1. Copy the [private profile](../../toolkit/templates/private-profile.md) to a
   private location.
2. Write one purpose and one question.
3. Fill evidence, counterevidence, and unknowns for only the relevant
   dimension.
4. Use a range or `unknown`.
5. Name one next question or evidence condition.
6. Set a review trigger.

Stop there.

Do not create a full career plan from one assessment.

## Private means private

Blank templates are public. Filled records usually are not.

Do not put a completed record in:

- this repository;
- public or shared source control;
- a public AI service;
- an unapproved document store;
- a shared team channel;
- a dashboard;
- an HR or talent system.

Use storage appropriate to the sensitivity and rules of the context. Plain
Markdown provides portability, not encryption or access control.

## Private profile and shared conversation

Keep these separate.

### Private profile

May contain:

- tentative interpretation;
- personal questions;
- uncertainty;
- private decision criteria;
- evidence not needed by another person.

### Shared conversation

Contains only:

- permitted purpose;
- necessary observable evidence;
- relevant context;
- the question or request;
- an agreed next action;
- review and deletion conditions.

Never solve oversharing by making the whole private profile collaborative.

## Historical snapshots

When a profile changes:

1. preserve the old date and context;
2. state what evidence changed;
3. do not rewrite old uncertainty as certainty;
4. do not compare numeric deltas as velocity;
5. retire records whose purpose no longer exists.

A history table of scores alone is not sufficient. Keep the material evidence
and context or discard the number.

## File naming

Use a neutral purpose rather than a person's name when practical.

Examples:

```text
2026-08-07-current-advocacy.md
2026-08-07-context-pathway.md
2026-08-07-role-diligence.md
2026-08-07-manager-transition.md
```

Names do not provide security. Storage and access controls still matter.

## Review triggers instead of reminders

Useful triggers:

- next resource or scope decision;
- next relevant senior review;
- completion of the bounded action;
- manager or reporting change;
- written response to a commitment;
- new evidence that contradicts the record;
- a material privacy or safety concern.

If nothing relevant occurred, `holding`, `paused`, or `unknown` may remain the
responsible state.

## One action at a time

Choose an action that is:

- observable;
- bounded;
- within legitimate authority;
- safe enough;
- supported with needed resources;
- reversible where possible;
- capable of producing relevant evidence.

Examples:

```text
publish one attribution note after a shared delivery
invite the domain owner to one decision forum
clarify who owns one changed commitment
ask one specific manager-practice question
delegate one decision class with rollback
```

Avoid:

- "network more";
- "be more visible";
- "fix E";
- "get promoted";
- "make the manager like me";
- repeated confrontation;
- unlimited relationship labor.

## Conversation protocol

Before:

- identify a permitted purpose;
- decide what not to share;
- consider power and retaliation;
- prepare one specific question;
- use a safer channel if direct inquiry is unsafe.

During:

- separate observation from inference;
- ask for examples;
- preserve disagreement;
- do not demand disclosure of private conversations;
- agree on one next action or evidence condition.

After:

- record the commitment and owner;
- correct factual errors;
- set the review trigger;
- remove unnecessary shared material;
- route serious concerns outside LIFT.

## Toolkit anti-features

The toolkit intentionally has no:

- composite health score;
- pattern classifier;
- prediction;
- recommendation engine;
- person ranking;
- manager leaderboard;
- team average;
- demographic correction;
- automatic reminder;
- digital-exhaust collection;
- AI inference;
- centralized database;
- HRIS integration;
- software service.

These are deletion targets, not missing features.

## When not to make a record

Do not create a LIFT record when:

- the question can be answered in an ordinary work note;
- the evidence would require surveillance;
- the purpose is an employment decision;
- the person cannot safely contest shared claims;
- protected information would become central;
- a qualified formal process already owns the issue;
- the record would create more risk than learning;
- there is no owner for correction or deletion.

Sometimes the safest operating practice is not to record.

## Software admission gates

Software remains deferred.

A software proposal must first show:

1. independent practitioners repeatedly use the plain templates;
2. a specific unmet need persists after simplification;
3. software removes real burden rather than adding score collection;
4. no prohibited employment-decision use is enabled;
5. local or user-controlled storage is considered first;
6. a data-flow and threat model covers collection, access, export, retention,
   deletion, breach, coercion, and secondary use;
7. the person can inspect, correct, export, and delete where permitted;
8. protected and demographic data remain outside individual profiles;
9. abuse cases and anti-retaliation risks pass independent review;
10. a shutdown and data-deletion path exists.

No dashboard or AI prototype is justified by the existence of Markdown
templates.

## Toolkit maintenance

When a source module changes:

1. update the authoritative module first;
2. identify affected toolkit fields;
3. remove obsolete fields;
4. update examples;
5. preserve compatibility only when it does not retain unsafe semantics;
6. record the change in Module 10 learning.

Templates follow modules. Modules do not bend to preserve a template.

## What this module does not claim

- Keeping a record improves career outcomes.
- More frequent scoring improves accuracy.
- A template makes a conversation safe.
- Markdown is secure storage.
- A private score should be shared.
- A dashboard is the natural next step.
- Software is required to operate LIFT.
- One toolkit fits every role or workplace.
- A completed form is better than an unanswered question.
